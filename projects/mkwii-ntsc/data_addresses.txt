# ---------------------------------------------------------------- Notes
# * No PAL binary is available on this machine (both MKW images found are RMCE01), so PAL-side offsets are
#   PAL_addr - PAL_r13/r2 by definition; each NTSC-U instruction above was matched by function identity (port table +
#   PAL MAP name), by the instruction's role in the SDK/EGG function, and by consistency with sibling globals.
# * .sbss gap: delta 0x4380 is directly witnessed up to PAL 0x80386F27 (EGG::Screen gScreenScale Vector2f at
#   PAL 0x80386F20/24 -> NTSC 0x80382BA0/A4: EGG_Screen_cpp_sinit_@8023e38c [d02da320] stfs f1,-0x5ce0(r13),
#   @8023e390 stfs f1,4(r4) with @8023e380 addi r4,r13,-0x5ce0; EGG::Screen::SetTVModeDefault@8023e1cc lwz r6,-0x5cec(r13)
#   = PAL 0x80386F14 active-screen ptr), and delta 0x4388 at PAL 0x80386F60 (sSystem). The extra 8 PAL bytes therefore
#   lie in PAL 0x80386F28..0x80386F5F (NTSC 0x80382BA8..0x80382BD7: EGG::Screen/StateGX statics); which object was
#   added/removed could not be identified without the PAL binary. None of the identities above fall inside that window.
# * The runtime's comment labels for some DVD .sbss globals do not match the SDK roles visible in the code
#   (0x80386664 is the flag DVDPause sets / DVDResume clears, 0x80386668 the one DVDResume tests-and-clears,
#   0x80386670 the one __DVDPrepareReset tests); the address identities are unaffected.
